# 企业知识库 RAG 运行手册

## 1. 系统目标

本系统面向内部书籍、制度和技术手册，提供可追溯的检索增强生成（RAG）。每个回答必须带有来源引用；证据不足时明确说明无法从资料中确认，不得编造。

## 2. 文档接入规范

支持 PDF、Markdown 和 TXT。导入前计算文件 SHA-256；相同 SHA-256 内容跳过重复解析，内容变化则替换旧版本索引。单文件上传限制 50 MB。文件名应包含业务域和版本号，敏感资料必须放入对应 library。

扫描 PDF 先尝试文本提取；没有文本层时进入 OCR。OCR 置信度低于 0.85 需要人工抽查，表格和页眉页脚应在抽查时重点确认。

## 3. 分块与索引

按标题和段落分块，保留章节路径、页码和原文哈希。块之间使用少量重叠，避免跨句截断。BM25 适合精确术语、编号和错误码，向量检索适合语义相似表达。两路结果使用 Reciprocal Rank Fusion（RRF）融合，因为它避免直接比较不可比的原始分数。

## 4. 重排与上下文

先取较大的候选集，再用轻量重排器结合问题词覆盖、标题匹配和位置特征排序，最后只把前 N 个块送入生成模型。重排服务不可用时回退到融合排序，并记录 degraded=true，不能静默改变行为。

## 5. 回答与引用

生成提示词要求只依据上下文回答，并在句末使用 [S1]、[S2] 引用。引用校验失败最多重生成一次；再次失败则返回证据摘要和失败状态。对资料没有覆盖的问题，应明确回复“当前资料未找到依据”。

## 6. 权限与安全

查询不能跨 library，检索接口必须携带当前用户的 library 范围。API 密钥只从环境变量读取，不写入配置、日志或评测报告。上传文件需要校验扩展名、大小和路径，禁止通过文件名写出工作目录。

## 7. 评测与上线门禁

离线集同时测 Recall@K、MRR、答案忠实度、上下文精确度，并对不可回答问题单独测拒答率。RAGAS 可用 DeepSeek 等开源或兼容模型作为评审器，但不能替代人工抽样。与基线相比，任一核心指标下降超过 5 个百分点禁止上线；每次发布至少人工抽查 20 个问题。

## 8. 故障处理

导入失败先查看文件类型、编码和 OCR 日志。检索为空时检查 library 权限和索引状态。模型超时可重试一次，仍失败则返回检索证据并标记 degraded=true。所有故障都要保留 trace_id 以便复盘。
